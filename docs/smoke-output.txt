## Notes on the run

- The `spec accept` step rewrites `examples/demo-order-pipeline/.meridian.yaml`.
  The shipped fixture was restored from git right after this capture, so the
  example keeps its two seeded findings.
- Accepting merges, it does not overwrite. The reviewed deny rule
  `draft -> refunded` survived the merge, which is why the check after accept
  still fails on it.
- The merge also adds newly observed edges to the allow list, so the second
  seeded finding (`unverified_shipping -> shipped`, not-allowed) became an
  allowed edge. That is the merge contract: deny rules are authoritative, an
  observed edge is proposed as allowed.
- The merge rewrites the file with its own header comment, so a hand-written
  comment above `machines:` is not preserved.
- The ledger stores event names, machine ids and aggregate counts. It does not
  store verdicts, file:line anchors, spec revisions or source revisions, and
  its SHA-256 chain is unkeyed: it detects edits, but anyone with write access
  to the ledger file can recompute the chain.
